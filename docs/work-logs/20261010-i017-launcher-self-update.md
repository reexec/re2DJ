## 2026-10-10 — 구현 / Implementation

- `re2dj/update/`(공용 코어): rePIU의 `semantic_version`, `release_info`, `sha256`, `release_archive`, `update_install`, `launcher_updater`를 이름 공간·`.re2dj-*` 접미사·저장소(`reexec/re2DJ`)·사용자 에이전트를 바꿔 옮겼다. 빌드 버전은 `re2dj::VersionString()`. 자산 이름은 `re2DJ-v<ver>-windows-x86.zip`, `-linux-x64.tar.gz`, `-linux-x86.tar.gz`이고 `FindReleaseAsset`은 대소문자를 무시한다(v0.0.70까지의 `re2dj-v…`도 찾음).
- 바뀐 점: 업데이터가 OS 함수를 기본 fetch로 부르던 것을, 호출자가 넘기게 했다(공용 코어가 OS 코드를 링크하지 않도록; 없으면 `kUnavailable`). 릴리스 JSON의 객체 멤버를 `std::pair<std::string, JsonValue>` 벡터에서 두 개의 평행 벡터로 바꿨다(clang 21 + libstdc++ 15가 정의 중인 타입의 pair를 거부).
- 플랫폼: `platform/https_download.h`, `linux/https_download.cpp`(시스템 `curl`), `windows/https_download.cpp`(WinHTTP, `winhttp` 링크). `self_process.h`에 `SelfExecutablePath`, `RunExecutableAndWait`, `ReplaceSelfProcess`(Linux `execve`), `ClearEnvironmentVariable`.
- 런처: `[Launcher] check_updates`, 화면 제목 아래의 알림 줄·Update/Retry·진행 막대·`kInstallUpdate`, 세션의 업데이터 생성(`RE2DJ_UPDATE_CHECK`, `RE2DJ_UPDATE_CURRENT_VERSION`)·남은 `.re2dj-old` 정리·설치·다시 시작.
- CMake: miniz에서 `MINIZ_NO_ARCHIVE_APIS`를 빼고 코어에 링크, `src/update/` 6개, OS별 다운로드 파일.
- 산출물 이름: `package_release.sh`·`.ps1`, `release.yml`의 workflow artifact, 사이트 안내 문구(`docs/sites/i18n`), `scripts/README.md`, `releases.py` 주석을 `re2DJ-v<ver>-<platform>`로. 실행 파일은 `re2dj` 그대로.
- 단위 테스트 `launcher_update_test.cpp`: rePIU probe를 옮기고(13개 묶음), x86 자산을 소문자 `re2dj-v…`로 두어 대소문자 무시를 확인한다. GCC 15의 `-Wdangling-pointer` 오탐을 피하려고 위험 경로 아카이브를 변수로 먼저 만든다. `launcher_test`에 `check_updates`.
- 문서: 가이드 `docs/guides/launcher-update.md`와 색인, README, ARCHITECTURE, IMPLEMENTED, THIRD_PARTY_NOTICES(miniz의 쓰임).

  *`re2dj/update/` (shared core): rePIU's `semantic_version`, `release_info`, `sha256`, `release_archive`, `update_install` and `launcher_updater`, carried over with the namespace, `.re2dj-*` suffixes, repository (`reexec/re2DJ`) and user agent changed; the build's version is `re2dj::VersionString()`; assets are `re2DJ-v<ver>-windows-x86.zip`, `-linux-x64.tar.gz` and `-linux-x86.tar.gz`, and `FindReleaseAsset` ignores case (finding `re2dj-v…` up to v0.0.70). Changes: the updater no longer defaults its fetch to the OS function; the caller passes it, so the shared core links no OS code (without one, `kUnavailable`); the release JSON's object members moved from a vector of `std::pair<std::string, JsonValue>` to two parallel vectors (clang 21 with libstdc++ 15 refuses a pair of the type being defined). Platform: `platform/https_download.h`, `linux/https_download.cpp` (the system `curl`), `windows/https_download.cpp` (WinHTTP, linking `winhttp`); `SelfExecutablePath`, `RunExecutableAndWait`, `ReplaceSelfProcess` (Linux `execve`) and `ClearEnvironmentVariable` in `self_process.h`. Launcher: `[Launcher] check_updates`, the notice under the title with Update/Retry, a progress bar and `kInstallUpdate`, and the session creating the updater (`RE2DJ_UPDATE_CHECK`, `RE2DJ_UPDATE_CURRENT_VERSION`), removing leftover `.re2dj-old` files, installing and restarting. CMake: `MINIZ_NO_ARCHIVE_APIS` dropped and miniz linked into the core, the six `src/update/` files, the per-OS download files. Artifact names: `package_release.sh` and `.ps1`, `release.yml`'s workflow artifacts, the site text (`docs/sites/i18n`), `scripts/README.md` and a `releases.py` comment now say `re2DJ-v<ver>-<platform>`; the executable stays `re2dj`. Unit test `launcher_update_test.cpp`: rePIU's probe carried over (13 groups), the x86 asset named in lower case `re2dj-v…` to check case is ignored, and the dangerous-path archives built first to avoid a GCC 15 `-Wdangling-pointer` false positive; `check_updates` in `launcher_test`. Documents: the guide `docs/guides/launcher-update.md` and its index, README, ARCHITECTURE, IMPLEMENTED and THIRD_PARTY_NOTICES (miniz's use).*
